# Accounts, currencies, cards and profile

Objective: one account per currency (ARS by default, USD optional) with its own alias and cards, dollar buy/sell at a simulated rate, and a Perfil screen.
Branch: `feat/accounts` (from `feat/transfers` at 72b0f05). Delivery strategy: `single-pr` (the user chose one PR for the previous feature). Test runner: Vitest. Absorbs `odd/tasks/cards.md`.

## Specs

- S1. "cada usuario debe tener un alias asociado a su cuenta, debe ser modificable en una nueva pantalla Perfil donde se podrán modificar el nombre, apellido, direccion, teléfono, mail y alias, además de tener una foto de perfil por defecto, también cosas como Moneda preferida".
- S2. "por defecto en toda la aplicación debe ser ARS en vez de USD y además agregar el '$' adelante, ejemplo $5000 para ARS 5000 y USD$5000 para 5000 dólares". Assumption: Argentine separators, so `$5.000` and `USD$5.000`, decimals with a comma.
- S3. "Por defecto será en ARS, salvo que se indique lo contrario, luego, el usuario tiene algun alias en dólares o tarjetas en USD que slo podrán hacer transferencias y operaciones en dólares". Model chosen by the user (option 1): the balance belongs to the account; each user has one ARS account and may have one USD account; each account has its own alias and its cards. A transfer only goes between accounts of the same currency.
- S4. "se indicará en una pantalla para comprar dólares (o vender) con una cotización simulada de ARS 1500 , si compro dólares se descuenta de la tarjeta que se indique el saldo en ARS y si vendo dólares se decuentan esos USD y se sumarán esos ARS al saldo de una tarjeta a la cotización que simulamos". Assumption: under the account model, the user picks the card, and the money moves between the accounts of the selected cards; one rate (1 USD = ARS 1.500) for both directions.
- S5. From cards.md: "deben poder añadirse más tarjetas, a la hora de crear el formulario para dar de alta una tarjeta, debe validarse si es Visa, Master o American Express, no es necesario conectarse a una API o algo por el estilo pero algo básico para mostrar como pensamos el producto". Local validation: prefix, length, Luhn, expiry not in the past, CVV length per brand. Only brand, last 4 digits, holder and expiry are stored; the full number and CVV never are.
- S6. Assumptions for Perfil: changing the email (the login identifier) requires the current password; address and phone are optional; the default photo is an avatar with initials; "Moneda preferida" picks the account shown first on Home and used by email transfers. Perfil is a bottom-navigation destination.
- S7. Assumption: a USD account is opened from the dollar screen ("Abrir cuenta en dólares"); the seed gives the main user both accounts.
- S9. "en la pantalla de perfil hay que hacer unos cambios: no pueden aparecer todos los formularios abiertos, por ejemplo, el alias debe decir el alias y luego un botón o tab para modificarlo, lo mismo el mail o si quiero cambiar la contraseña, recién ahí se me debe renviar a una pantalla con los inputs necesarios". Assumptions: changing the password needs the current one, the new one has at least 8 characters and is typed twice, and other sessions are closed.
- S10. "Vamos a agregar una funcionalidad en la página de Perfil, añadir un tema oscuro además del claro". Assumptions: light stays the default; the choice is per device (stored in the browser and applied before the first paint, so it also covers the login page); colors move to theme tokens.
- S11. "El logout deberá estar al final de la pantalla de Perfil en vez de en la barra inferior". Added to T9 because it touches the same files.
- S12. "los últimos movimientos que aparecen en la pantalla de inicio serán 5 o 6 y tendrá un botón de Consultar todos, los registros deben ser los últimos movimientos independientemente de la tarjeta, se detallará en el mismo registro (ejemplo, tarjeta terminada en 8845)". Assumptions: Home lists the latest 6 across all accounts; movements record their card (the chosen card for dollar exchange, the account's first card for transfers; existing movements are backfilled with their account's first card); rows show "Tarjeta terminada en 8845", or the account when there is no card.
- S13. "En la pantalla de Tarjetas, al hacer click en la tarjeta se podrán consultar movimiento realizados con esa tarjeta y ver los detalles de la misma (nombre, últimos números, cuando vence, lo que consideres)". Assumptions: `/cards/[cardId]` for the owner only; details are brand, last four digits, holder, expiry with an expired or expiring-soon note, its account (currency and alias) and the date it was added; below, the movements made with that card, with loading and empty states. Depends on T10 (card on each movement).
- S14. "Los últimos movimientos serán agrupados por fecha y se podrá filtrar por fecha en la pantalla de todos los movimientos". Assumptions: movement lists (Home and Movimientos share the component) group rows under "Hoy", "Ayer" or the date, in Buenos Aires time; Movimientos adds date filters (Hoy, Últimos 7 días, Este mes, and a Desde/Hasta range) kept in the URL and combined with the search and type filters.
- S15. Review slice 5 found that balances are 32-bit integer cents, so an account tops out at $21.474.836,47 and a credit past it fails with a generic error. User decision: "Cambialo a bigint". Balances and stored amounts become BIGINT (widening only, no stored value changes); per-operation limits stay as they are.
- S16. "En la pantalla de transferencias preguntar si se desea guardar el contacto antes de guardarlo por defecto". Assumptions: the confirmation step offers an unchecked "Guardar a <nombre> en mis contactos" only when the recipient account is not a contact yet; the transfer saves the contact only when it is checked, in the same transaction; existing contacts and favorites are untouched.
- S17. User decision: the Home balance card uses the app-wide format, `$978,85` / `USD$978,85`, without the currency badge (added to T13).
- S18. "Cambiar los nombres de las rutas a nombres en español y más concisos o descriptivos". Mapping: /login→/ingresar, /home→/inicio, /movements→/movimientos, /transfers→/transferir (/new→/nuevo, /to/[accountId]→/[cuentaId], /confirm→/confirmar, /success/[id]→/comprobante/[id]), /exchange→/dolares (/confirmar, /comprobante/[id]), /cards→/tarjetas (/new→/nueva, /[cardId]→/[tarjetaId]), /profile→/perfil (/personal→/datos, /email, /alias/[cuentaId], /password→/contrasena, /currency→/moneda), /services→/servicios, /top-ups→/recargas; Query parameters stay as they are (user: "Los parámetros no hacen falta pasarlos a español, pero sí las rutas"). Code identifiers stay in English.
- S19. User decision: database tables and columns in Spanish with Prisma `@@map`/`@map`, code identifiers in English ("En español con @map"). Assumptions: snake_case names (e.g. `usuarios`, `sesiones`, `cuentas`, `tarjetas`, `contactos`, `transferencias`, `movimientos`, `operaciones_cambio`; `saldo_centavos`, `monto_centavos`, `moneda`, `creado_en`), Spanish enum type names; enum values stay (ARS, USD, SENT…) because they are data; a rename-only migration that keeps every row, constraint and index (constraints and indexes renamed to match); raw SQL in the lock queries rewritten.
- S8. Existing stored money is never relabeled: the migration keeps each account's stored currency; only the default changes to ARS.
